# Проверка v0.2

```bash
make test
make build
./start.sh
```

Go: race detector, расчёты счётчиков, частичные ошибки, остановка/возобновление и HTTP-граница. Vue: строгий TypeScript и production generate. После генерации Go-тест проверяет доступность встроенных `/_nuxt/` и MIME CSS.

Интеграция требует явной `TEST_DATABASE_URL` в **выделенную тестовую БД**: очищаются samples и изменяется service_settings. Проверяются запись без дублей, сохранение отключённого состояния и истории при повторном открытии БД, очистка, min/max и null при пропусках.

```bash
TEST_DATABASE_URL='postgres://user:password@127.0.0.1:5432/goinmetrics_test?sslmode=disable' \
  go test -race ./...
```

CI создаёт собственную PostgreSQL, собирает Nuxt, проверяет типы, Go и race detector. Ничего не публикует.

## Проверка остановки

1. Выключить мониторинг. PUT подтверждается после завершения очереди; health.monitoring_enabled=false, queue=0.
2. Подождать больше двух секунд: collected, время snapshot и число сохранённых точек не меняются. История читается.
3. Во второй вкладке появляется тот же статус, без ложного сообщения о потере соединения.
4. Перезапустить приложение. Отключённое состояние сохраняется, сбор сам не начинается.
5. Включить: первый CPU/сеть — подготовка, следующие — достоверные значения. Интервал остановки остаётся разрывом.
6. `./stop.sh`: оба контейнера stopped; `./start.sh`: данные и настройки остались.

## Интерфейс

Проверены Chrome 1440 px и 390 px: отсутствие хедера/событий, обе темы, сохранение темы и скрытия сайдбара после reload, возврат панели, документация, навигация, CSV, пауза просмотра и остановка в двух вкладках. Inter проверен через Font Loading API с кириллицей; запросов к внешним доменам и ошибок JavaScript нет. Светлая тема использует отдельные цвета графиков, границ, поверхностей и текста.

## Измерения

Результаты и воспроизводимая методика в [performance.md](performance.md). Для сборщика:

```bash
go test ./internal/collector -run '^$' -bench BenchmarkCollect -benchmem -benchtime=3s -count=3
```

Для Go и PostgreSQL при реальной секундной работе и нескольких SSE-зрителях:

```bash
python3 scripts/benchmark.py --seconds 60 --output /tmp/goinmetrics-performance.json
```

Замеры не заменяют суточное испытание на целевом VPS и сравнение задержек вашего приложения до/после включения мониторинга.

## Итог проверки полного выключения

`./stop.sh` перевёл оба контейнера в exited. После запуска из локального образа настройка осталась выключенной, collected=0, число сохранённых снимков совпало с числом до остановки. После явного включения появились новые корректные CPU/сетевые значения. Обычный `./start.sh` использует локальный образ и не запускает сборку; пересборка выполняется через `./start.sh --build`.

## Оформление панели

После обновления проверены тёмная и светлая темы, синие акценты и отсутствие CSS-градиентов. Удалены рекламные подписи, пояснения под графиком и точки в заголовках. Основные подписи имеют размер 13–14 px. Значок светлой темы содержит окружность и восемь лучей.

В Chrome на 1440 и 390 px язычок остаётся в пределах экрана и совпадает с краем сайдбара во всех кадрах анимации, при скрытой панели и прокрутке. Скрытие сохраняется после перезагрузки; кнопка остаётся доступной вне inert-содержимого. Проверены мобильная документация, отсутствие обрезанных текущих значений и горизонтальной прокрутки. TypeScript и production-сборка прошли; ошибок JavaScript нет.

## Готовая поставка и сравнение

Проверки загрузчика (без Docker daemon) запускаются `python3 -m unittest discover -s scripts/tests -v`: обычный запуск не компилирует, отсутствие готового образа не вызывает скрытую сборку, архив проверяется перед импортом, неверная архитектура отклоняется, кешированный образ не импортируется повторно. CI/release проверяются actionlint.

`cd web && npm test` проверяет взвешенное среднее, пики, null, нулевую базу, локальное время и валидацию интервалов. PostgreSQL-тест проверяет отсутствие двойного учёта общей границы. В Chrome проверены два запроса истории, отсутствие фонового опроса за 31 секунду, совпадение среднего с данными API, общий масштаб и валидация до обращения к БД; мобильная ширина 390 px без переполнения корневой страницы.

Оба образа собраны локально, multiarch OCI-индекс проверен: linux/amd64 и linux/arm64. ARM64 ELF — статический aarch64; выполнение на ARM-хосте не проверялось. Архив amd64 испытан как отдельная новая установка: перед запуском убрана только его новая локальная метка образа, загрузчик импортировал образ из архива, создал .env с 0600, поднял изолированную PostgreSQL и сохранил точки. Компиляция не выполнялась. После проверки удалены только временные контейнеры и тома.

Release workflow прошёл actionlint. На GitHub не запускался и публикация не выполнялась из-за отсутствия подключённого доступа. Готовые локальные архивы лежат в dist/; инструкции выпуска — releases.md.
